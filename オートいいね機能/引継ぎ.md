### 手順5: 記事ページのセレクタと既スキ状態の確定

- `shared/adapters/note-browser.js` `_likeState()` は `aria-pressed` → `aria-label` の文言 → class 名の順に判定する。実際の属性に合わせ、**押下前に `liked` / `not_liked` が確定する**ようにする。`unknown` のままだと実行器は「既スキ状態を確認できない」として保留にする（送信しない）。これは安全側の仕様なので、確定できる根拠がない限り緩めない。

## 4. 変更するときの約束（依頼書に由来）

- 取得できない値を捏造・補完しない（日時・件数・userId・既スキ状態）。不明は不明のまま保留にする
- 収集日時・初回発見日時を反応日時に転用しない。取得順を最新順と決めつけない
- 教材の例示（数十・数千、500/200）を必須条件にしない。閾値は設定値にし、未設定なら判定しない
- 一人につきスキはプロジェクト全体で1件。日付変更・モード変更・再収集で成功済みを再対象化しない
- 結果不明は自動再送しない。再試行前に現在の状態を照合する
- 対象不足は件数未達で終了。無作為補充・条件緩和・他アカウントへの再割当で埋めない
- 外部制限・認証要求は内部残数より優先。IP・VPN・プロファイル変更で回避しない
- パスワード・Cookie・認証トークンを台帳・ログ・設定に書かない。Chrome のセッションを使うだけ
- 勝手なテスト投稿・スキ解除・削除・VPN 変更・メール変更をしない。既存の投稿・予約・アカウント設定を変更しない
- 実アカウントでの送信と定期実行は初期OFF。開始は利用者の明示操作のみ
- 画面に「自動化で成果が保証される」「200件なら安全」と表示しない

## 5. 設計の要点（変更時に壊さないこと）

- `shared/rules.js` は純粋関数。時計は引数。境界: `0 <= now - publishedAt < 14日`、同数不採用、不明は保留
- `shared/ledger.js` の `reserve()` は `BEGIN IMMEDIATE` 内で `UPDATE ... WHERE state='candidate' AND account_id=?` の `changes===1` を見る。`sending` は `releaseReservation()` でも期限切れでも戻らない。`finish()` は `run_id` 一致かつ `reserved/sending` のみ
- `shared/limits.js` の `canExecute()` の判定順: 外部制限 → 未設定 → 内部残数 → 日次(JST) → 時間 → 最小間隔。`consume()` は送信開始時（`markSending` 直後）。ドライランでは呼ばない
- `shared/runner.js` の `_processReserved()` は 本人 → 最新記事と再評価 → 記事詳細 → ページを開いて本文・既スキ → （ドライランはここで予約解放） → 送信開始 → 結果 の順。`unknown` は既定で run を止める
- アダプタ契約（`getCurrentUser / getCreator / getCreatorNotes / getNoteLikes / getFollowers / getNote / openAndReadNote / like / close`）は `shared/adapters/mock.js` が正。実アダプタの戻り値の形を変えるときはモックとテストも合わせる
